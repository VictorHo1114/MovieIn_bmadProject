# 壓力測試指南

##  測試前檢查清單

### 1. 確認後端運行
```powershell
cd backend
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

### 2. 安裝測試依賴
```powershell
pip install aiohttp
```

### 3. 執行診斷
```powershell
python scripts/diagnose_performance.py
```

確認：
-  連線池配置: Pool Size 50, Max 150
-  pgvector 索引已建立
-  Embedding 資料 100% 填充
-  Redis 快取可用（可選）

##  執行壓力測試

### 模式 1: 完整測試（約 5 分鐘）
測試 7 個階段：4, 6, 8, 10, 15, 20, 50 RPS

```powershell
cd backend
python scripts/stress_test.py
```

### 模式 2: 快速測試（約 1 分鐘）
僅測試關鍵階段：6, 10, 50 RPS

```powershell
cd backend
python scripts/stress_test.py quick
```

##  測試階段說明

| 階段 | RPS | 時長 | 目的 |
|------|-----|------|------|
| 1. 初始 | 4 | 30s | 建立健康基準線 |
| 2. 穩定攀升 | 6 | 30s | **之前崩潰點**，驗證修復 |
| 3. 性能臨界 | 8 | 30s | 觀察連線池壓力 |
| 4. 負載尖峰 | 10 | 30s | **之前超時點**，驗證改善 |
| 5. 全面壓力 | 15 | 30s | 推向極限 |
| 6. 極限測試 | 20 | 30s | 找出新崩潰點 |
| 7. 目標驗證 | 50 | 30s | **Priority 1 目標** |

---

##  成功標準

### Priority 1 目標（50 RPS）：
-  成功率  95%
-  P99 延遲 < 1,000ms
-  平均延遲 < 500ms
-  無超時錯誤

### 健康狀態等級：
-  **健康**: 成功率 99%, P99 <1000ms
-  **警告**: 成功率 95%, P99 <2000ms
-  **阻塞**: 成功率 80%, P99 <5000ms
-  **崩潰**: 成功率 <80% 或大量超時
-  **死亡**: 系統無回應

##  監控重點

### 測試期間觀察：
1. **後端日誌**: 查看連線池使用情況
2. **響應時間**: 是否線性增長
3. **錯誤率**: 有無連線超時
4. **系統資源**: CPU/記憶體使用率

### 診斷命令（另開終端）：
```powershell
# 實時監控
while ($true) {
    python scripts/diagnose_performance.py
    Start-Sleep -Seconds 10
}
```

---

##  問題排查

### 如果仍出現連線池滿載：
1. 檢查 Neon 計劃是否支援 150 connections
2. 檢查推薦系統是否有慢查詢
3. 考慮啟用 Redis 快取
4. 檢查 WebSocket 是否佔用連線

### 如果 P99 延遲過高：
1. 檢查 pgvector 索引是否生效
2. 檢查 Embedding 快取命中率
3. 優化推薦算法邏輯
4. 考慮增加 Neon 計算資源

### 如果出現超時：
1. 增加 `pool_timeout` (當前 60s)
2. 檢查 Neon 是否有冷啟動延遲
3. 檢查網路連線品質
